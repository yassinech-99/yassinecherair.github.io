Building an SSH server from scratch for an LLM agent

How I wrote a minimal SSH server in Python so Ansible could talk to a fake network device.

April 10, 2026

Open in harness → /?read=building-ssh-server-from-scratch

The problem

At InfraXcode we were building a network device emulator — an LLM that pretends to be a Cisco router. The goal: let engineers run their real Ansible playbooks against it without changing a line.

Ansible connects over SSH. So the emulator needed to speak SSH.

Why not use an existing library?

Paramiko has a server mode. It works. But it gives you raw bytes and you’re responsible for the entire session loop — channel requests, pty negotiation, exec vs shell channels, keepalives. The documentation is thin and most examples on the internet target the client side.

I ended up reading the RFC and working through it by hand. It was worth it.

What the server actually needs to handle

For Ansible compatibility, a minimal SSH server needs to support:

  1. Key exchange and host key — Ansible checks the host key on first connect. You need to generate one and persist it, or Ansible will refuse.
  2. Password or key auth — we used password for simplicity in the dev environment.
  3. Session channel — Ansible opens a session channel, sends an exec request with the command string, reads stdout/stderr, and checks the exit code.
  4. No pty — Ansible does not request a pty for exec-based connections. If you only implement shell channels you’ll get nowhere.

The tricky part is exit status. Ansible parses it to decide if a task succeeded. If your server never sends an exit-status message the connection hangs.

Hooking the LLM in

Once the transport layer was done, the handler was simple:

  1. Receive the exec command string (e.g. show ip interface brief).
  2. Pass it to the LLM with the current session context.
  3. Stream the response back as stdout bytes.
  4. Send exit-status 0, close the channel.

The LLM never sees the SSH layer. It just gets a string and returns a string.

What broke in testing

  • Ansible gather_facts sends a Python script over SSH, not a CLI command. We had to detect and short-circuit that path.
  • Connection reuse — Ansible pipelines multiple exec requests over one SSH connection. The server needs to handle multiple channel opens without tearing down the session.
  • Timeout on slow LLM responses — Ansible has a default timeout. Long responses from a slow model would cause spurious failures. We solved this by streaming tokens as they arrived rather than buffering the full response.

Result

Real Ansible playbooks, written for real Cisco devices, ran against the emulator with no modifications. Task success rates tracked closely with what you’d get on physical hardware.

The SSH server ended up being about 200 lines of Python on top of Paramiko’s Transport class. Not much code for what it unlocks.
