Automating network inventory collection and NetBox sync

Replacing manual spreadsheet updates with automated inventory collection across Cisco, ACI, and Palo Alto — synced to NetBox.

November 20, 2025

Open in harness → /?read=network-inventory-automation

The situation

The client had a few hundred network devices across several sites — Cisco IOS/IOS-XE switches and routers, an ACI fabric, and Palo Alto firewalls managed through Panorama. Their source of truth was a spreadsheet. It was always wrong.

Updates happened manually after changes were made to devices. When they happened at all. Most of the time the spreadsheet reflected what the network looked like six months ago.

The ask: automate inventory collection and sync it to NetBox so the CMDB is actually accurate.

Collection approach

Three different device types, three different collection methods.

Cisco IOS/IOS-XE — SSH + TextFSM. Connect via Paramiko or Netmiko, run show version, show interfaces, show ip interface brief, show cdp neighbors detail. TextFSM templates parse the unstructured CLI output into structured dicts. Cisco’s NTC-templates library covers most of the common commands; we wrote a few custom templates for edge cases.

Cisco ACI — REST API. ACI exposes everything through a well-documented REST API over HTTPS. Query the APIC for tenants, VRFs, bridge domains, EPGs, and endpoint tables. JSON responses, no parsing needed. The main challenge: the ACI object model is deep and the relationships are non-obvious if you haven’t worked with it before.

Palo Alto Panorama — XML API. Panorama has an API that returns XML. Less ergonomic than JSON but complete. We pulled device groups, security policies, address objects, and interface configs.

NetBox sync

NetBox has a REST API and a Python library (pynetbox). The sync logic:

  1. Collect current state from devices.
  2. Pull current state from NetBox.
  3. Diff the two.
  4. Apply creates, updates, and — carefully — deletes.

Deletes needed a manual approval gate. Automated deletes from a sync script that has a bug can wipe your CMDB. We flagged stale records for review instead of deleting them automatically.

The diff logic was the most work. NetBox’s data model doesn’t map 1:1 to what devices report. An interface on a device becomes an interface object on a device object on a site object in NetBox. The reconciliation needed to handle partial matches — device exists but interface doesn’t, interface exists but IP changed, and so on.

Running it

The collection scripts ran on a schedule via AWX (the open-source Ansible Tower). A playbook triggered the Python inventory scripts, aggregated the results, and called the NetBox sync. AWX gave us scheduling, credential management, and job history without building that infrastructure ourselves.

Outcome

Manual inventory effort dropped by around 80%. The remaining 20% was edge cases — devices that weren’t reachable via the standard methods, ACI objects with non-standard naming that needed manual classification, and the occasional device that needed a template fix.

More importantly: when something changed on the network, NetBox reflected it within an hour instead of never. Other automation that depended on NetBox as a source of truth (IPAM, cable tracing, change management) got more reliable as a result.

What I’d change

The TextFSM approach works but it’s brittle. Any time Cisco ships a firmware that changes output formatting, a template breaks. NETCONF + YANG is the right long-term answer — structured output by design, no parsing. The problem in practice: a lot of older IOS versions in the field don’t support NETCONF, and the ones that do have incomplete YANG coverage. TextFSM stays relevant longer than it should.
